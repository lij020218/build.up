# iOS 디자인 개편 계획 — 애플 자사앱 기준 (2026-09-12)

> 목표: "요소가 한 번에 너무 많이 들어있는" 지금 화면을, 애플 자사앱처럼 **한 화면 = 한 가지 일**로 정리한다.
> 이 문서는 ① 현재 분석 ② 조사 근거 ③ 적용 규칙 ④ 단계별 실행 계획 순이다. 미리보기 화면은 실제 시뮬레이터 렌더.

## 1. 현재 앱 분석 (실제 화면 캡처 기준)

캡처: `홈 / 로드맵 / 마케팅 / 세금 / 직원 / 내 정보` 6화면.

### 1-1. 구조적 문제

| # | 문제 | 근거(현재 코드·화면) | 결과 |
|---|---|---|---|
| A | **콘텐츠가 유리 위에 놓임** | 전역 Aurora 그라디언트 배경 + 카드 `white.opacity(0.72~0.88)` | 글자 대비가 배경에 따라 변함. iOS 26 원칙과 정반대 |
| B | **카드 안의 카드(3중첩)** | `BUCard` 스타일 5종(heroOuter 24 / outer 20 / nested 18 / headline 16 / inner 14) | 반경 5단계·테두리 3겹. 홈 히어로는 카드 안에 카드 안에 카드 |
| C | **한 화면에 주인공이 여럿** | 홈: 배너 + 세그먼트(오늘/운영/더보기) + 인사카드 + 매출카드 + 집중카드 + 차트 + KPI 3종 | 무엇부터 볼지 알 수 없음. 주요 액션이 특정되지 않음 |
| D | **칩 과다** | 홈 한 줄에 `248일째`·`성장`·`↗+4%` 3개, 로드맵 행마다 `현재`·`잠금` | 정보가 아니라 장식으로 읽힘 |
| E | **타이포 스케일 난립** | 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5pt — 14pt 미만만 8종 | 위계가 안 생기고, 작은 글자가 많아 밀도가 높아 보임 |
| F | **고정 폰트 크기** | `Font.system(size:)` 일변도, Dynamic Type 미대응 | 글자 크게 쓰는 사장님이 못 씀(접근성) |
| G | **탭바가 콘텐츠를 가림** | 각 화면이 `Color.clear.frame(height: 110)` 스페이서로 회피 | 회피지 해결이 아님. 마지막 행이 잘림 |
| H | **영문·한글 라벨 병기** | 내 정보: `ACCOUNT · 계정` + `계정 정보` | 같은 말을 세 번 |

## 2. 조사 — iOS 26 / 애플 자사앱 디자인

### 2-1. 가장 중요한 발견: Liquid Glass 는 **네비게이션 레이어 전용**

- 유리 재질은 **탭바·툴바·떠 있는 버튼·시트** 등 "콘텐츠 위에 뜨는 것"에만 쓴다.
  **리스트·카드 같은 콘텐츠 레이어는 예전 그대로 불투명**하게 둔다.
- **글자는 유리 위에 직접 놓지 않는다.** 항상 불투명 면 위에.
- 유리 위에 유리를 겹치지 않는다(중첩 금지).
- 대비 4.5:1 이상 유지.

→ 우리 앱은 정확히 반대로 하고 있다(배경은 그라디언트, 콘텐츠 카드는 반투명, 탭바만 시스템 기본).

### 2-2. 레이아웃·타이포 수치

- 큰 제목 34pt Bold / 소제목·본문 17pt / 보조 15pt / 캡션 13pt / 탭바 라벨 11pt.
- 8pt 그리드, 화면 마진 16~20pt, 최소 탭 타겟 44×44pt, 터치 요소 간 8pt.
- 리스트 행 = 좌측 아이콘 + 텍스트 + 우측 액세서리(셰브론/값) 3분할.
- 한 화면에 한 가지 일 + 주요 액션 1개. 관련 있는 것은 좁게, 없는 것은 넓게. **선보다 여백이 더 깨끗한 구분자**.

### 2-3. iOS 26 신규 도구

- `.tabBarMinimizeBehavior(.onScrollDown)` — 스크롤하면 탭바가 접힌다. (G 문제의 정식 해법)
- `ConcentricRectangle` / `.containerShape` — 중첩 시 안쪽 반경 = 바깥 반경 − 패딩으로 자동 계산.
- `GlassEffectContainer` + `.glassEffect()` — 유리 요소를 하나의 표면으로 합침(개별 적용 금지).
- ⚠️ **우리 앱 최소 지원 버전은 iOS 18** (`Package.swift .iOS(.v18)`, `project.yml 18.0`).
  → iOS 26 API 는 전부 `if #available(iOS 26.0, *)` 로 감싸고, 18에서는 기존 동작으로 떨어뜨린다.

### 2-4. 2026 일반 트렌드(애플 계열)

- 근백색/근흑색 배경 + **액센트 1개** + 본문색 1개 + 보조색 1개로 앱 전체를 끌고 간다.
- 큰 타이포와 넉넉한 여백. 정보는 줄이는 게 아니라 **계층으로 접는다**.

## 3. 적용 규칙 (개편안 디자인 토큰)

```
배경   흰색 + 상단 푸른 글로우         (2026-09-12 사장님 선택. 전역 오로라 그라디언트는 제거)
       글로우: 중심 (0.5, -0.04~-0.12) 반경 화면폭×1.0~1.15, #4A6CF0 최대 20~30% → 투명
       화면 위 1/3 안에서 사라지므로 카드가 놓이는 영역은 사실상 흰색 = 대비 일정
표면   카드/리스트 흰색 불투명         (opacity 사용 금지)
       흰 배경 위 흰 카드 → 경계선 7% 0.5pt + 그림자 y3/blur10 5% 로만 띄운다
글자   #11131A / 55% / 35%            (3단)
액센트 미드나잇 #191970 — 주요 액션·현재 상태에만
상태색 긍정 #1F7A45 · 주의 #B8860B · 위험 #B64C4C  (그 외 색 사용 금지)

타이포 34 Bold(대제목) / 22 Bold(카드 제목) / 17(본문) / 15(보조) / 13(캡션)
       11pt 미만 금지. 숫자는 monospacedDigit.
간격   화면 마진 20 / 카드 패딩 18 / 섹션 간 24 / 행 높이 최소 52
모서리 카드 20 하나만 (중첩이 없으니 단계가 필요 없다)
유리   탭바·툴바·시트에만. 콘텐츠는 불투명. (글로우는 재질이 아니라 배경 그래픽)
칩     한 줄에 최대 1개. 상태(진행 중·위험)에만.
```

**화면 작성 규칙 3줄**
1. 이 화면이 시키는 **한 가지 일**을 맨 위 카드에 두고, 버튼도 하나만 둔다.
2. 나머지는 **섹션 제목 + 행 리스트**로 내린다. 카드 안에 카드를 만들지 않는다.
3. 색은 "지금 해야 할 것"과 "위험"에만 쓴다. 나머지는 흑백 + 여백.

## 5. 실행 계획 (4단계, 각 단계가 독립 배포 가능)

> **진행 상태 (2026-09-12 저녁)** — 1단계 배경·카드 적용 완료, 2단계 탭바 완료.
> 아래 각 항목 뒤 `[완료]` / `[남음]` 참고. 커밋은 아직 하지 않았다.

### 1단계 — 기반 토큰 교체 (가장 큰 효과)
- **[완료]** `BUColor` 에 `appBackground`·`canvasGlow`·`canvasGlowOpacity`·`subtleFill` 추가.
  `BUBackgroundSurface` 본체를 `BUCanvasBackground`(흰 바탕 + 상단 글로우)로 교체 —
  셸이 한 곳에서 쓰므로 전 화면이 함께 바뀌었다. 로그인 화면은 자체 배경이라 영향 없음.
- **[완료]** `BUCard` 시각을 2단으로 평탄화 — 바깥 카드만 흰 면 + 0.5pt 헤어라인 + 옅은 그림자,
  안쪽 블록은 `subtleFill` 평면(테두리·그림자·inset 하이라이트 제거).
  (스타일 enum 5종은 호출부 호환 위해 남겨 두고 **렌더 결과**를 2종으로 묶었다.)
- **[완료]** 웹 캔버스 동일 적용 — `globals.css` 의 베이지 `--bg` + `body::before/::after`
  오로라 2겹을 **흰 배경 + 상단 글로우 1겹**으로 교체, `--surface` 를 불투명 흰색으로.
  오로라 키프레임(80s·110s 상시 애니메이션) 제거.
- **[완료]** 웹↔iOS 동기화 가드: `apps/web/__tests__/canvas-tokens-ios-sync.test.ts` (6개).
- **[완료]** 카드 비율을 미리보기에 맞춤 (사장님 2026-09-12 "카드도 이 느낌으로"):
  모서리 24/20/18/16/14 **다섯 단계 → 20 하나**(안쪽 경고 박스만 16),
  카드 여백 14~16 → **18 통일**, 섹션 간격 18 → **24**, 화면 좌우 margin 12 → **16**
  (화면마다 12/16 으로 갈려 있던 것도 함께 통일).
- **[완료]** 카드 곡률 — 20 → 26 으로 올렸다가 **12 로 확정**.
  사장님 재지시(2026-09-12): "각진 직사각형에서 모서리만 둥근 걸 원한다". 26 은 뭉툭했다.
  **근거**: 애플 HIG 는 수치를 공표하지 않고 "연속 곡률, 큰 면은 평평한 변 + 부드러운 모서리"라는
  질적 지침만 둔다. 애플이 자사앱에서 실제로 쓰는 값은 **inset grouped 리스트 섹션 10pt**
  (설정·메일·메모의 흰 묶음) — 정확히 "직사각형에 모서리만 둥근" 모양이다.
  흔히 인용되는 "22.37% + 스무딩 60%"는 **앱 아이콘 템플릿** 역산값이지 일반 UI 규칙이 아니다.
  → 카드 12 / 안쪽 면 8 / 버튼 10. 카드를 10 이 아니라 12 로 둔 건 안쪽 8 이 동심으로 보이게
  하려는 것(iOS 26 ConcentricRectangle 의 "바깥 반경 − 여백" 계산과 같은 취지).
  웹은 값이 **133곳에 직접 박혀 있어** 한 번에 바꿀 수가 없었다 → `--card-radius` 토큰으로 묶고
  129곳을 치환했다(브랜드 랜딩 2곳·80×80 아이콘 타일 1곳은 제외 — 검정 배경·고정 크기 타일).
- **[완료]** 카드 안 구획(`.nested`)을 **회색 블록 → 0.5pt 구분선**으로.
  홈 히어로가 "흰 카드 안에 회색 블록 3개"였다 — 미리보기처럼 흰 면이 이어지고
  구분선 하나로만 나뉜다. 제목·구분선용 공용 컴포넌트 `BUSectionTitle` / `BUHairline` 추가.
- **[완료]** 웹 카드도 같은 규칙 — `operationalStyles.ts` 4개 카드의
  180deg 그라디언트 → 불투명 흰색, 1px 테두리 → 0.5px 헤어라인,
  2겹 그림자 → 얕은 1겹, headlineCard 모서리 16 → 20. (데스크톱 여백 밀도는 유지)
- **[완료]** 로고 아래 배경 단차 제거 (사장님 신고 2026-09-12).
  원인: 셸이 캔버스를 그리는데 **재무·보고서·주간·운영·성장 5개 화면이 자기 ScrollView 에도
  `.background(BUBackgroundSurface())` 를 걸어** 글로우가 브랜드 바 아래에서 다시 시작됐다.
  실측: 재무 화면 114pt 지점에서 rgb(246,248,254) → (241,244,254) 로 역행(Δ10.2).
  조치 두 가지 —
   ① 중복 배경 5곳 제거(탭 화면은 NavigationStack 이 없어 셸 캔버스가 그대로 비친다).
   ② `BUCanvasBackground` 의 글로우를 **화면 전역 좌표 기준**으로 바꿈 — 로드맵·시트처럼
      자체 배경이 꼭 필요한 곳(NavigationStack 이 불투명 배경을 칠함)에 한 번 더 깔려도
      같은 그림이 나온다. 같은 실수가 다시 나도 단차가 생기지 않는다.
  검증: 재무·보고서·로드맵·홈 4화면 재측정 → 단차 0. 브랜드 상세 시트도 정상.
- **[남음]** 타이포 40여 개 alias → 5단 축소 + Dynamic Type.
  `Font.system(size:)` 호출이 **2,945곳**이라 기계적 일괄 치환은 고정 프레임과 충돌해
  전 화면 레이아웃이 깨질 위험이 크다. 별도 작업으로 분리 — 아래 "결정이 필요한 것" 4번.
- 영향: 전 화면. **검증**: 홈·로드맵·프랜차이즈·마케팅·내 정보·세금·재무·보고서·메뉴재료
  9개 화면 실기기(시뮬) 캡처로 흰-바탕 충돌 없음 확인. 배경 실측 상단 rgb(246,248,254) → 하단 (255,255,255).

### 2단계 — 셸·네비게이션
- **[완료]** 화면마다 박혀 있던 `Color.clear.frame(height: 110)` 스페이서 **17곳 제거**.
  대신 셸이 `.safeAreaInset(edge: .bottom)` 으로 한 번만 여백을 잡는다
  (`BUTabBarMetrics` + `.buBottomTabClearance()`). 값이 110/100 으로 갈라져 있던 것도 함께 해소.
  → 스크롤 인디케이터가 바 아래로 내려가지 않고, 새 화면에서 빠뜨릴 수 없다.
- **[완료]** 탭 바 재질 `ultraThinMaterial` → `regularMaterial`.
  흰 캔버스에서는 ultraThin 이 뒤 글자를 그대로 비춰 "깨진 글자"로 읽혔다.
  캡슐 높이도 `BUTabBarMetrics.barHeight` 로 고정해 인셋 계산과 어긋나지 않게 했다.
- **[남음]** `.tabBarMinimizeBehavior(.onScrollDown)` — 네이티브 `TabView` 전용 API 인데
  현재 탭 바는 커스텀 오버레이다. 셸을 `TabView` 로 바꾸는 리팩터가 선행돼야 한다.
- **[남음]** 큰 제목(`.navigationTitle` + large) 통일, 커스텀 `BUPageHeader` 정리.
- **[남음]** 홈의 세그먼트(오늘/운영/더보기) 제거 — 탭과 역할이 겹친다.

### 3단계 — 화면별 재구성 (우선순위 순)

**공용 부품 먼저 (2026-09-12 완료)** — 사장님 지시: "내부 요소도 애플스러운 것으로 교체".
화면마다 카드·행을 손으로 다시 만들던 것이 복잡함의 뿌리였다. 실측:

 ② 홈은 **직원이 있는 점주에게만** 직원 구획을 "오늘 할 일" 바로 아래에 자동 승격(오늘 근무자·승인 대기 N건),
    직원 0명이면 아예 숨김(빈 카드 금지),
