## Part 0. 설계의 대전제 — "최고"의 정의

우리 기준 3개 (모두 통과해야 '최고'):

1. **진짜 문제를 해결하는가?** — 흑자부도, 번아웃, 시간 부족

# Part 1. Cash-flow Crunch Tracker 정밀 설계

## 1-1. 사용성 분석 — 가장 근본적인 질문 5개

### Q1. 점주는 언제 이 기능을 쓰는가?
실제 사용 시점 시뮬레이션:
- **매일 아침 8시**: 출근 지하철에서 "오늘 통장 얼마?" 확인 (30초)
- **재고 주문 결정 전**: "이거 시키면 돈 괜찮나?" (1분)
- **직원 채용 전**: "한 명 더 뽑아도 되나?" (2분)
- **월 중순 불안할 때**: "월말까지 버틸 수 있나?" (3분)
- **푸시 알림 수신 시**: 72시간 전 위기 경고 → 즉시 확인

**핵심 인사이트**: 평균 사용 시간은 **30초~1분**. 모바일 우선. 긴 화면 스크롤 금지.

### Q2. 어디서 접근하는가?
- 메인 대시보드 **최상단** (로그인 → 2초 내 눈에 들어와야 함)
- 모바일 웹 (PC 전용 불가)
- 카카오톡 채널 위젯 (Phase 2) — "매일 아침 8시 통장 알림"

### Q3. 가장 원초적인 3가지 질문
| 질문 | 답을 주는 데 필요한 데이터 |
|---|---|
| "오늘 내 통장 얼마?" | 현재 잔고 (수동 입력 또는 은행 연동) |
| "내일/모레 얼마 더 들어와?" | 정산 예정일 × 채널별 수수료 제외 금액 |
| "내일/모레 얼마 나가야 해?" | 고정비 캘린더 (월세, 급여, 대출 등) |

**이 3개만 답하면 MVP 완성.** 다른 건 다 사족.

### Q4. 데이터는 어디서 오는가? (가장 어려운 문제)

**현실**: 배민·쿠팡이츠는 자영업자 대상 공식 API가 없음. 스크래핑은 법적 회색지대.

**3단계 현실적 접근**:

| 레벨 | 방법 | 난이도 | MVP에 포함? |
|---|---|---|---|
| **L1** | 사용자 수동 입력 (채널별 매출 비율 + 현재 통장 잔고) | 쉬움 | ✅ **P1-Zero** |
| **L2** | POS API 연동 (토스/KIS/스마트로) — 카드 매출 자동 | 중간 | Q3 (Phase 2) |
| **L3** | 배민 스크래핑 / 네이버페이 SMS 파싱 | 어려움 + 법적 리스크 | 보류 |

**P1-Zero MVP는 L1만** — 기존 dailyEntries 입력 시 채널 스플릿 필드 추가.

### Q5. 위기 감지 시 무엇을 할 수 있어야 하는가? (원버튼 액션)

72시간 내 현금 부족 예상 시 제시할 옵션 (사용자는 **1탭으로 선택**):

```
⚠️ 3일 후 통장 잔고 -48만원 예상

가능한 행동 (우선순위 순):
1. [배민 광고비 이번 주만 5만원 감액]    → 딥링크로 배민 광고 설정 열기
2. [이번 주말 할인 쿠폰 발급해 매출 부스트] → Coupon Agent 연동
3. [공급처에 결제 5일 연기 요청]          → 카톡 메시지 초안 생성
4. [소상공인 정책자금 긴급대출 조회]        → 소진공 홈페이지 딥링크
5. [직원 근무시간 조정 논의]              → 직원 카톡 메시지 초안
```

**원칙**: 각 액션은 **외부 앱 딥링크 + 자동 메시지 초안**. 우리 서버에서 실제 실행은 Phase 2.

## 1-3. 데이터 모델 설계

### 신규 스토어: `cashflow-store.ts`

```typescript
// ─── Types ───

export type SalesChannel = {
  id: "cash" | "card" | "baemin" | "coupangeats" | "yogiyo" | "naverpay" | "kakaopay" | "other";
  label: { ko: string; en: string };
  salesRatio: number;           // 0~100 (%), 전체 매출 중 비율
  settlementDays: number;        // 정산까지 일수 (cash=0, card=2, baemin=7)
  commissionRate: number;        // 수수료율 (%) — 배민 6.8, 쿠팡이츠 9.8
  paymentFeeRate: number;        // 결제 수수료 (PG별) — 대부분 3.3~3.5
  isActive: boolean;
};

export type FixedExpenseSchedule = {
  id: string;
  label: string;                 // "월세", "직원 급여", "대출 이자"
  amount: number;
  dayOfMonth: number;            // 1~31, "매월 25일"
  category: "rent" | "payroll" | "loan" | "utilities" | "supplies" | "other";
  isActive: boolean;
};

export type CashProjection = {
  date: string;                  // ISO "2026-04-18"
  inflow: number;                // 그날 입금 예상
  outflow: number;               // 그날 지출 예상
  balance: number;               // 그날 종료 잔고 예상
  breakdown: {
    channel: string;
    amount: number;
    type: "inflow" | "outflow";
    label: string;
  }[];
};

type CashFlowState = {
  currentBalance: number;        // 사용자 수동 입력 현재 잔고
  currentBalanceUpdatedAt: string; // 언제 업데이트했는지 (오래되면 경고)
  salesChannels: SalesChannel[];
  fixedExpenses: FixedExpenseSchedule[];
  crisisThresholdDays: number;   // 기본 3일 — 이 날짜 내 음수 → 경고
  notifyOnCrisis: boolean;
  dailyMorningBriefing: boolean;
};
```

### 계산 로직 핵심

```typescript
// 14일 예상 현금 흐름 계산
function projectCashFlow(
  currentBalance: number,
  recentDailySales: number,        // 최근 7일 평균 일매출
  channels: SalesChannel[],
  expenses: FixedExpenseSchedule[],
  days: number = 14
): CashProjection[] {
  const projections: CashProjection[] = [];
  let balance = currentBalance;
  const today = new Date();

  for (let i = 0; i < days; i++) {
    const date = new Date(today);
    date.setDate(today.getDate() + i);
    const dateIso = date.toISOString().slice(0, 10);
    const dayOfMonth = date.getDate();

    // 오늘의 예상 매출 = avg × 채널별 비율
    // 채널별 매출 중 "i일 전 매출"이 오늘 정산되는 것 합산
    let inflow = 0;
    const breakdown: CashProjection["breakdown"] = [];

    channels.filter(c => c.isActive).forEach(channel => {
      // i일 전 이 채널 매출이 오늘 들어옴 (settlementDays 일 후 정산)
      const originalSalesDay = i - channel.settlementDays;
      if (originalSalesDay >= -30 && originalSalesDay < 0) {
        // 과거 30일 내 매출 → 이미 발생한 매출 (실측)
        // → 실제로는 과거 dailyEntries에서 조회
        // MVP는 recentDailySales 평균값 사용
        const grossAmount = recentDailySales * (channel.salesRatio / 100);
        const netAmount = grossAmount * (1 - channel.commissionRate / 100 - channel.paymentFeeRate / 100);
        inflow += netAmount;
        breakdown.push({
          channel: channel.id,
          amount: netAmount,
          type: "inflow",
          label: `${channel.label.ko} 정산`,
        });
      }
    });

    // 고정비 지출
    let outflow = 0;
    expenses.filter(e => e.isActive).forEach(expense => {
      if (expense.dayOfMonth === dayOfMonth) {
        outflow += expense.amount;
        breakdown.push({
          channel: expense.category,
          amount: expense.amount,
          type: "outflow",
          label: expense.label,
        });
      }
    });

    balance = balance + inflow - outflow;
    projections.push({ date: dateIso, inflow, outflow, balance, breakdown });
  }

  return projections;
}

// 위기 감지
function detectCashCrisis(
  projections: CashProjection[],
  thresholdDays: number = 3
): { willCrisis: boolean; crisisDay: string | null; shortfallAmount: number } {
  const within = projections.slice(0, thresholdDays);
  const negative = within.find(p => p.balance < 0);
  if (!negative) return { willCrisis: false, crisisDay: null, shortfallAmount: 0 };
  return {
    willCrisis: true,
    crisisDay: negative.date,
    shortfallAmount: Math.abs(negative.balance),
  };
}
```

# Part 2. Action Agents 정밀 설계

## 2-1. 설계 철학 — 원버튼의 진짜 의미

Gemini의 지적: "예쁜 대시보드 = 합리적 결정"은 오만.

**원버튼의 조건 4가지**:
1. **상황 인식**: AI가 자동 감지 (사용자가 일 안 벌리게)
2. **구체적 제안**: 숫자와 텍스트가 완성된 상태 (사용자가 안 채워도 됨)
3. **1탭 실행**: 외부 링크 or 우리 서버에서 직접 처리
4. **되돌리기**: 2분 내 언두 가능 (잘못 눌렀어도 복구)

**원버튼이 아닌 것**:
- ❌ "이런 거 해보세요" + 긴 설명
- ❌ 사용자가 숫자 입력해야 하는 것
- ❌ 탭 → 새 화면 → 또 탭 → 또 탭

## 2-2. 4개 Agent 상세 설계

### Agent A: Coupon Agent (쿠폰 자동 발급)

**트리거 (자동 감지)**:
- 지난 7일 매출이 지난 14일 평균 대비 15%+ 하락
- 평일 14-17시 한산 시간대 감지
- 재고 유통기한 3일 이내
- (Phase 2) 경쟁사 신메뉴 출시

**UI**:
```
┌─────────────────────────────────────────────┐
│  🎟 쿠폰 제안                                │
│                                              │
│  지난 주 매출 -18% (₩2.1M → ₩1.7M)           │
│                                              │
│  추천: 평일 점심 30% 할인 3일간              │
│  ─ 코드: LUNCH30                              │
│  ─ 기간: 4/19 (금) ~ 4/21 (일)              │
│  ─ 한도: 100매                                │
│  ─ 예상 회복: +₩50~80만원                    │
│                                              │
│  [🚀 카톡 채널에 발송]  [수정]  [건너뛰기]  │
└─────────────────────────────────────────────┘
```

**원버튼 [🚀 카톡 채널에 발송] 처리**:
1. marketing-store의 promoCodes에 즉시 추가 (isActive: true)
2. FirstCustomersCard의 쿠폰 탭에 표시
3. 카카오 채널 API 딥링크 열기 (Phase 2: 자동 발송)

## 2-4. Agent 데이터 모델

### 신규 스토어 확장: `agents-store.ts`

```typescript
export type AgentKind = "coupon" | "reorder" | "content" | "review";

export type AgentProposal = {
  id: string;
  kind: AgentKind;
  triggeredAt: string;           // ISO
  reason: string;                 // "지난 주 매출 -18%"
  proposal: {
    title: string;
    details: Record<string, unknown>;  // kind별 구조 다름
    previewText?: string;
  };
  status: "pending" | "accepted" | "skipped" | "undone";
  acceptedAt?: string;
  skippedAt?: string;
  outcome?: {
    // 실행 후 측정되는 결과
    metric: string;                // "sales_recovery", "stock_restored"
    expectedValue?: number;
    actualValue?: number;          // 7일 후 측정
  };
};

type AgentsState = {
  proposals: AgentProposal[];
  enabledAgents: Record<AgentKind, boolean>;   // 끌 수 있게
  lastTriggerCheck: string;                     // 중복 제안 방지
};
```

1. **Prompt caching 반드시 적용** — 90% 원가 절감
2. 비즈니스 컨텍스트 (매장 정보, 최근 매출)는 **2시간 TTL**로 재사용
3. Agent 트리거 감지 = 로컬 계산 (API 호출 X), **LLM은 제안 생성에만**

## 7-2. Phase 2 자동실행 설계 — 사용자에게 설명

### 업계 표준 패턴 (Reco.ai, Galileo, LangChain)
1. **위험도 분류 (Risk Classification)**:
   - **Low**: 알림 없이 자동 실행 가능
   - **Medium**: 알림 + 10초 유예 후 자동 실행 (취소 가능)
   - **High**: 반드시 사용자 명시적 승인
2. **Pre-action approval**: 실행 전 승인
3. **Post-action review**: 실행 후 언두 (2분 창)
4. **Conditional approval**: 금액·횟수 한도 기반

### 우리 4개 Agent의 위험도 매핑
| Agent | Phase 1 (지금) | Phase 2 (자동) | 이유 |
|---|---|---|---|
| **Coupon** | 원탭 승인 | **Medium** — 한도 내 자동 | 재정 영향 있지만 제한 가능 |
| **Reorder** | 원탭 승인 | **Medium** — 금액 한도 자동 | 재고 주문, 공급처 계약 고려 |
| **Content** | 원탭 승인 | **High** — 항상 수동 | 브랜드 평판, 실수 시 타격 큼 |
| **Review** | 원탭 승인 | **Low** — 자동 링크 생성 | 링크 복사일 뿐, 위험 낮음 |

### Phase 2 사용자 플로우 (설명)

**상황**: 김사장님이 3개월째 build.up을 쓰며 Agent가 제안하는 쿠폰을 매번 승인해왔다. "매번 똑같이 승인하는데 자동화할 수 없나?"

**Phase 2 작동 방식**:

```
┌─ 설정 → 자동실행 Agents ─────────────────┐
│                                            │
│ 🎟 쿠폰 Agent                              │
│ ☑ 자동 발급 허용                           │
│   ─ 할인율 한도:  [ 30 ]% 이내             │
│   ─ 월 총 할인 한도: [ 20 ]만원 이내       │
│   ─ 유효기간: 7일 이내만                   │
│   ─ 발급 전 10초 유예 후 자동 실행         │
│                                            │
│ 📦 재주문 Agent                             │
│ ☑ 자동 주문 허용                           │
│   ─ 건당 한도: [ 10 ]만원 이내             │
│   ─ 월 총 한도: [ 50 ]만원 이내            │
│   ─ 정해진 공급처만 (목록: 3곳)            │
│                                            │
│ 📸 콘텐츠 Agent                             │
│ ☒ 자동 실행 불가 (항상 확인 필요)          │
│                                            │
│ ⭐ 리뷰 Agent                               │
│ ☑ 링크 자동 생성 (실제 발송은 수동)        │
│                                            │
└────────────────────────────────────────────┘
```

### 실제 실행 화면 (Phase 2)

```
┌─ 푸시 알림 ──────────────────────────────┐
│ 🎟 매출 -18% 감지, 쿠폰 자동 발급 예정  │
│                                            │
│ 10초 후 자동 실행:                         │
│ "주말 20% 할인 쿠폰 50매"                  │
│                                            │
│ [지금 실행] [10초 후 자동] [취소]         │
└────────────────────────────────────────────┘
```

### Phase 2 보호장치 (Guardrails)
1. **하드 한도 (변경 불가)**:
   - 쿠폰: 1회 30% / 월 30만원 이내 (시스템 강제)
   - 재주문: 건당 20만원 / 월 100만원 이내
   - 1일 자동 실행 최대 3건 (Agent 종류 상관없이)

2. **소프트 한도 (사용자 설정)**:
   - 위 UI에서 사용자가 더 낮출 수 있음

3. **실행 로그**:
   - 모든 자동 실행 기록 (영구 보관)
   - 주간 리포트: "이번 주 Agent가 한 일 5건, 예상 효과 +32만원"

4. **긴급 정지**:
   - 설정에서 "모든 자동 Agent 일시 정지" 버튼 (1탭)
   - 사용자가 반복적으로 언두하면 해당 Agent 자동 비활성화 (ML 신호)

### Phase 2 출시 시점
- Phase 1 (원탭 승인)로 **3개월 데이터 축적**
- 사용자별 승인 패턴 학습 → Phase 2 초대
- **자동실행은 Pro/Business 플랜 전용** (수익 차별화)

## 7-3. 업계 표준 KPI — 조사 기반 재정립

### 업계 벤치마크 (2026)
- **B2B SaaS NPS 평균**: 41 (중간), <$1M ARR은 25
- **NPS >50 그룹**: 연간 churn <5%, 재방문율 40% 낮음
- **좋은 NPS**: 30~50, 50+ 엑설런트, 80+ 월드클래스
- **Activation rate**: 업종별 상이, B2B SaaS 평균 30~40%

### build.up North Star Metric (단 1개)
**"Weekly Active Operators" (WAO)** — 주 3회 이상 접속하는 활성 경영자 수
- **근거**: Slack "Weekly Active Teams" 벤치마크, 우리 vision "매일 의존하는 파트너"
- **입력 지표 (leading indicators)**:

| 지표 | 계산 | 목표 (6개월 후) | 업계 벤치마크 |
|---|---|---|---|
| **Activation Rate** | 가입 → 14일 내 매출 입력 + 채널 설정 | **45%+** | B2B SaaS 30-40% |
| **4W Retention** | 가입 4주 후 주 3회+ 접속 | **35%+** | B2B SMB 25-40% |
| **Cash-flow Setup Rate** | 대시보드 접근자 중 채널/고정비 설정 완료 | **60%+** | (신규 기능, 자체 설정) |
| **Agent Accept Rate** | Agent 제안 → [적용] 탭 | **30%+** | AI 제안 수락률 업계 20-40% |
| **NPS** | 분기 1회 설문 | **>35** (mid-market target: 40-50) | B2B SaaS 평균 41 |
| **Monthly Churn** | 월 이탈률 | **<8%** (첫 해 목표, 성숙 단계는 <5%) | NPS>50 그룹 <5% |
| **Free→Pro 전환율** | 월 기준 | **8%+** | Freemium 평균 2-5%, 강한 프로덕트 10%+ |
| **LTV:CAC** | 12개월 LTV / CAC | **>3:1** | SaaS 표준 3:1 (성공 기준) |

### 우리 고유 KPI (build.up만의 지표)
| 지표 | 의미 | 목표 |
|---|---|---|
| **Crisis Prevention Rate** | Cash-flow 위기 경고 수신 사용자 중 실제 회피 비율 (자기 보고 설문) | **70%+** |
| **One-button Execution Rate** | Agent 제안된 액션 중 [적용] 탭 비율 | **30%+** |
| **Cashflow Confidence Score** | 설문 "내 통장이 30일 뒤 얼마인지 아는가" 1-5점 | **3.8+ / 5** |

### PMF 측정 (Andreessen 40% rule)
- 분기 1회 설문: "build.up이 없어지면 얼마나 실망하시겠습니까?"
- **목표**: "매우 실망" 응답 **40%+**
- 40% 미달 시 → 제품 재검토, 40%+ 달성 시 → 성장 가속화

| 상태 | 배경 | 테두리 | 텍스트 | 톤 |
|---|---|---|---|---|

### "세련됨"의 구체적 규칙
- ❌ 원색 빨강 (`#ff0000`), 폭죽, 번쩍이는 애니메이션
- ✅ 미묘한 배경 틴트, 얇은 테두리, 명확한 타이포그래피
- ✅ 위기 아이콘: ⚠ 대신 **얇은 선 아이콘** (lucide-react의 `AlertTriangle` linear variant)
- ✅ "위기" 대신 **"주의가 필요해요"** 같은 부드러운 언어
- 예시:
  ```
  ❌  🚨 위기! 48시간 내 파산!!
  ✅  · 3일 후 통장이 마이너스로 전환될 수 있어요
  ```

### 한국어 + 영어 Copy 원칙 (Q6)
모든 신규 UI에 ko/en 모두 작성:
- 한국어: 부드럽고 동료 같은 톤 ("이렇게 해보는 건 어때요?")
- 영어: 간결하고 전문적 ("Consider this action")
- 숫자 포맷은 locale별 ($12,000 vs 1.2만원)
