# 상권 base_score SSOT 가이드 (2026-05-18)

> `public.market_location_signals.base_score` 의 채점 기준을 한 곳에서 정의한다.
> 새 entry 추가·기존 entry 갱신 시 반드시 이 가이드를 따른다.
> 이 문서가 깨지면 같은 수준 상권인데 점수만 다른 부조리가 발생한다.

---

## 1. 점수 의미

`base_score` 는 **0~100** 의 *절대* 척도. 사장님이 "이 상권은 객관적으로 얼마나 매력적인가?" 를 한눈에 비교할 수 있어야 한다.

- 사용자별 업종·예산·가중치는 별도 (`packages/shared/src/market/scoring.ts`) 가 보정.
- 이 base_score 는 *상권 자체의 강도* 만 표현한다.

---

## 2. 10대 평가 요소

채점은 10개 요소의 합산. 각 요소 0~10 점, 가중 합산 후 0~100 으로 정규화.

| # | 요소 | 가중치 | 측정 기준 |
|---|------|--------|----------|
| 1 | 일 유동인구 | 1.5× | 5만 미만(2) / 5~10만(5) / 10~20만(7) / 20만+(10) |
| 2 | 임대료 부담 (역상관) | 1.2× | 높을수록 감점. 적정 임대료=10 / 최고 수준=2 |
| 3 | 대중교통 접근성 | 1.0× | 환승역(10) / 단일 역세권(7) / 도보 10분(5) / 버스만(3) |
| 4 | 배후 수요 | 1.5× | 주거+직장+학교 다중 배후(10) / 단일 배후(5) / 약함(2) |
| 5 | 미래 호재 | 1.0× | 3년 내 GTX/신규노선·아레나·대규모 단지(10) / 5년 내(7) / 없음(3) |
| 6 | 경쟁도 (역상관) | 0.8× | 적정 경쟁(10) / 과열(4) / 포화(2) |
| 7 | 트렌드성·SNS | 0.8× | 핫 라이징(10) / 안정 인지도(7) / 정체(4) / 침체(2) |
| 8 | 외국인 비중 | 0.6× | 글로벌 관광지(10) / 일부 유입(5) / 없음(3) |
| 9 | 신축 단지 입주 | 0.8× | 12000+세대·진행 중(10) / 3000~12000(7) / 단지 외(3) |
| 10 | 재개발·도시재생 | 0.6× | 진행 중·확정(10) / 검토 중(5) / 없음(3) |

합산 후 가중치 총합 (1.5+1.2+1.0+1.5+1.0+0.8+0.8+0.6+0.8+0.6 = **9.8**) 으로 나눠 0~10 → ×10 으로 0~100.

## 5. market_style / rent_band / level enum 사용 규칙

| 컬럼 | 가능 값 | 사용 기준 |
|------|--------|----------|
| `market_style` | `destination` / `office` / `residential` | 90% 이상 단일 성격이면 그 값, 복합이면 우세 성격 |
| `rent_band` | `low` / `mid` / `mid-high` / `high` | 평당 임대료: <100만(low) / 100~250(mid) / 250~400(mid-high) / 400+(high) |
| `competition_level` | `low` / `mid` / `mid-high` / `high` | 도보 5분 내 동종 점포: <5(low) / 5~15(mid) / 15~30(mid-high) / 30+(high) |
| `demand_level` | `low` / `mid` / `mid-high` / `high` | 일 유동: <3만(low) / 3~10만(mid) / 10~20만(mid-high) / 20만+(high) |
| `access_level` | `low` / `mid` / `mid-high` / `high` / `strong` | 환승 3개+ 또는 GTX(strong) / 환승2(high) / 단일역세권(mid-high) / 도보(mid) |
| `category_fit_level` | `weak` / `moderate` / `mid` / `mid-high` / `strong` | 업종 적합도 (외식·카페·소매 등 광범위 적합(strong) / 일부만 적합(mid)) |

`access_level` 만 `strong` 별도 enum 값 있음. 다른 컬럼은 `strong` 사용 금지.

## 6. search_keywords 작성 룰 (카카오맵 매칭용)

`window.kakao.maps.services.Places().keywordSearch(keyword + region)` 가 이 배열의 *첫 항목* 을 검색에 사용한다고 가정. 따라서:

### 필수 포함
1. **공식 동·역 이름** (예: "신사동·신사역") — 카카오가 정확히 매칭하는 최소 단위
2. **상권 통칭** (예: "가로수길", "샤로수길")
3. **인접 동·역 5~10개** — 사용자가 어느 키워드로 검색해도 매칭
4. **랜드마크·앵커 시설** (예: "더현대서울", "롯데월드몰", "성신여대")
5. **구 이름** (예: "강남구")

### 첫 항목 룰
- 가장 정확하게 매칭되는 *역명 또는 동명* 을 첫 항목으로.
- 예: `'compdam-general'` → `['청담', '청담동', '청담역', ...]` 가 아니라 `['청담역', '청담동', '청담', ...]` — 카카오에 가장 정확한 매칭부터.

### 좌표가 명백한 곳은 region_name 자체에 좌표 키워드
- 예: `'강남역 상권'` → 카카오에서 "강남역" 으로 검색하면 정확한 좌표.
- 예: `'세로수길·도산공원'` → "세로수길" 또는 "도산공원" 모두 정확 좌표.

## 7. 신규 entry 생성 워크플로

1. **점수 결정**: §3 의 anchor 와 비교해서 점수대를 정한다. ±2 이내 범위로 미세조정.
2. **enum 채우기**: §5 의 룰로 6개 컬럼 모두 채운다.
3. **search_keywords 작성**: §6 의 룰로 최소 7개, 최대 15개. 첫 항목 = 카카오 정확 매칭 키워드.
4. **호재 반영**: §4 의 매크로 변수 적용 (이중 카운트 금지).
5. **summary 작성**: 한국어 1~2문장. 사장님이 한눈에 이해.
6. **evidence 작성**: `reasons` (강점 3~4개) + `warnings` (주의 2~3개) JSON.
7. **last_checked_at / next_review_at**: 오늘 / 6개월 뒤.

## 8. 점수 재조정 트리거

다음 중 하나라도 발생하면 `next_review_at` 기다리지 말고 즉시 재조정:

- **공실률 통계 발표** (분기별 한국감정원·지자체 자료)
- **신규 노선 개통 / 정차역 변경 발표**
- **대규모 단지 입주 시작** (사장님이 1년 일찍 알아야 함)
- **이태원 참사·코로나급 외부 충격** — 외국인 관광 상권 일괄 재검토
- **사용자 제보** — 사장님이 "이 상권 갔는데 망했다 / 핫하다" 보고

## 10. 자주 발생하는 오류 패턴

- **호재 이중 카운트**: GTX-C 호재로 청량리 +5 줬는데 동북선 호재로 또 +5 → 합 88+ → anchor 와 어긋남. 큰 호재 1개만.
- **anchor 무시**: "이 동네 좀 비싼 거 같아" 같은 인상으로 90 매김 → 실제 anchor (강남역 92, 명동 88) 와 동급은 절대 아님.
- **search_keywords 첫 항목이 일반어**: `['상권', '핫플레이스']` 류 → 카카오 검색 실패. 반드시 공식 동·역명.
- **연관 동·역 누락**: 사용자가 "○○동" 검색했는데 미매칭 → 인접 5km 내 모든 동을 keywords 에 포함.
